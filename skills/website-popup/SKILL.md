Read `references/popups-types.md` and `references/popups-rules.md`.

The goal is a popup that does one clear job for the shop without getting in the visitors' way.

First comes what it is for, unless the user said so: collecting email or SMS subscribers, an announcement or offer with a link (free shipping, a sale), or a notice such as cookies or privacy. A popup can also be a block inside the page instead of a window. The popup types reference maps each purpose to an objective.

For collecting subscribers, what the visitor gets (a discount, news, a contest) and whether it asks for email or a phone number come from the user. A SUBSCRIBE action needs the code of an interest list of the right channel.

The popups the business already runs, and how they perform, help avoid two popups competing on the same pages.

Short copy in the business language usually works best. A delay or exit intent is often kinder than showing the popup at once, and the cart and checkout pages are usually left alone unless the user asks.

Before asking for approval, check the launch with `validate_popup_launch` and fix what it lists, so the user approves a popup that can start. Show the user the copy, the display rules, and the audience. Launch only after the user approves that exact popup, and say that visitors see it within seconds.

The files named above are in the `references/` folder of this skill. They are copies of the resources the Leadhub MCP server serves, so the skill does not need to read those resources.
